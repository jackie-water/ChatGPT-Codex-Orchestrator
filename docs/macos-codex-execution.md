# macOS Codex execution lifecycle

This package implements the trusted local macOS Codex subprocess and its instance-scoped lifecycle. The executor stops at `EXECUTED_UNVALIDATED`; that state is not review readiness. After execution, `runtime/scripts/macos-finalize-codex.mjs` invokes the native wrapper-owned controller. Existing P0–P6 handoff boundaries and P2.2b.1 execution safeguards continue to govern. The default project iteration cap remains five.

Before any Git mutation, the finalizer requires the executor's private regular ledger with exact numeric project/issue/iteration identity, instance ID, zero exit, `NOT_RUN` validation, authorized repository and branch, canonical clone path, authorization digest, and valid pre/post/default SHAs. The digest binds the immutable authorized event, project configuration, validation argv, original Chat route, Control provenance and instance root. Caller mutations to the returned plan cannot change it. Older or uncertain ledgers without this link are rejected; they are never upgraded to review readiness. The completed input ledger remains unchanged, and its bytes are checked again at every source barrier.

Only the exact ledger-bound clone below the instance's private `automation` directory is eligible. Every path component, including the final clone directory and Git metadata, must pass the symlink checks. Linked worktrees and alternate object stores are rejected. Pass the canonical path recorded as `repo_path`; the finalizer does not resolve a caller-supplied symlink to authorize it. Both complete origin fetch and push URL sets must contain exactly one URL for the configured GitHub repository. Protected/default task branches, protected checkpoint branches, and a checkpoint branch equal to the task branch are prohibited. `checkpoint_branch` must be explicitly configured.

The remote default is verified as the executor's recorded commit, using `refs/remotes/origin/<default>^{commit}` rather than `origin/HEAD`. The post-Codex head must match the ledger and descend from the pre-Codex head. The wrapper stages changed files, checks index integrity, and commits when necessary with author/committer `Codex Orchestrator <codex-orchestrator@users.noreply.github.com>`. Git hooks and commit signing are disabled for wrapper operations. An already-clean or already-committed result retains its exact SHA and task branch.

Validation runs outside the Codex model loop. The native diff integrity check and the immutable structured, allowlisted argv run with `shell:false`, bounded output and secret redaction. Executables resolve to trusted files outside the source clone; shell executables and relative executable paths are rejected. The per-command timeout defaults to 30 minutes, with a maximum of 30 minutes. Each validator owns a private process group. On timeout or parent exit, the controller reconciles descendants, escalates TERM to KILL, and accepts only an `ESRCH` group probe as proof of absence. Unverified termination produces `UNKNOWN`. Every validator is followed by checks of the exact SHA, branch, origin, ledger and clean working tree. Validation-generated changes remain available as failure evidence.

Only a validated source is pushed. A missing remote task branch is valid for first publication; an existing head must be an ancestor of the exact source SHA. The controller reconciles remote movement and sends one non-forced push of that SHA to the authorized task ref. Every push result, including nonzero/timeout, is queried before settlement. A mismatch or unavailable query becomes `UNKNOWN`; there is no blind retry.

The wrapper publishes the immutable report at `.codex/runs/by-issue/<issue>/iteration-<iteration>__<sha12>.md` on the configured checkpoint branch. A private temporary index and Git plumbing preserve the source checkout. Existing reports for that logical iteration must match both path and bytes, otherwise publication fails closed. The report records `VALIDATED_SOURCE`, exact pre/post/source/default commits, changed files, validation output and verified source push. Final review readiness is a separate journal decision after publication and callback queuing. The controller records and verifies the exact `checkpoint_commit` and `checkpoint_path`; `.codex/latest-run.md` is never used or updated.

After publication, a durable journal intent precedes the original Chat's `[CODEX-AUTO callback_id=...]` record in the existing instance `pending-wakes` outbox. It contains the exact source SHA and checkpoint coordinates. New records remain `PENDING`; the finalizer does not send browser messages or declare delivery. Existing explicit-route-v1 receipt/delivery helpers reconcile verified user-role receipts. Replays preserve `DRAFT_INSERTED`, `SUBMISSION_ATTEMPTED` and verified `DELIVERED` state; they do not queue another payload or send again. A publication intent can finish initial callback queuing without repeating validation or pushes. If a completed callback record disappears, reconciliation fails closed rather than recreating a potentially submitted message. A later checkpoint descendant does not replace the original checkpoint coordinates.

An exclusive private finalization lock and journal live under `macos-finalization/<project>-<issue>-<iteration>.*`. Interrupted claims never authorize another commit, validator or push. Interrupted checkpoint push intents can query and verify their recorded commit/path before callback recovery. Other interrupted phases require reconciliation. Pre-SHA failures create original-route P1 incidents with no source SHA; subsequent failures include the recorded source SHA. Incidents use the existing `failure-outbox`, and failed validations become `VALIDATED_FAILURE`; uncertainty becomes `UNKNOWN`. Persistence errors retain the claim/intent and fail closed. No failed path returns `READY_FOR_REVIEW`.

The wrapper does not merge, deploy, clean, reset, or force-push the task workspace. It uses only the configured explicit Chat route and the existing pending-wake delivery/reconciliation lifecycle; there is no Chat fallback. Routine tests, lint, and diff review are executed by the wrapper outside the Codex model loop.

The CLI accepts `--event-path`, `--control-root`, `--control-repository`, `--trusted-github-username`, `--repo-path`, and optional `--timeout-ms`. It reauthorizes the original raw Control event and passes the resulting immutable plan to `finalizeMacosCodexRun`. Existing P1 duplicate-run barriers still apply to CLI reauthorization after an incident; recovery must retain the original authorized plan through the controller or reconcile that incident first. Never delete an uncertain claim to cause an automatic rerun.

Focused tests are in `tests/macos-postexecution-wrapper.test.mjs`. They create fake Control/route registries, a temporary HOME, a fake Codex child where needed, and local bare Git remotes. Only Git transport boundaries are adapted; source/index/object operations use the temporary repositories. No test needs real GitHub, a browser, or a real Codex job. The external wrapper/controller owns test execution and routine checks.
