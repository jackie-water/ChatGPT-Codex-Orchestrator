A binary in an accessible mode-0777 directory can be replaced after validation before spawn, potentially running an unauthorized executable.

Independent isolated Mac fixture constructed a fake executable owned by the current user and mode 0700 under an accessible 0777 parent directory. executeMacosCodexRun accepted and executed the fake binary; output: EXECUTABLE_PARENT_MODE=777 and EXECUTABLE_PARENT_WORLD_WRITABLE_ACCEPTED=true. No real Codex binary or credentials used.

Required correction if separately approved: verify ownership and directory write/execute permissions of resolved binary's parent chain, fail closed on group/world-writable nontrusted components while preserving normal user-owned Mac Codex installation paths, and spawn only the verified resolved binary. Account for legitimate macOS temporary and symlinked paths without relying solely on final file mode. Add isolated parent-chain, replacement-risk and normal-install fixtures.
